## Audio startup investigation and fix

There were two separate issues:

1. Screenshot error -2004287478 / 0x888900A is the Windows audio-device-in-use error. Saved settings were System/WASAPI shared, not ASIO. VirtualDJ was still running and was a plausible exclusive-device holder; user closed it. faderCraft was reopened afterward, with no stderr output observed. Audible playback still needs user confirmation.
2. Realtek ASIO startup probe reproducibly exited with 0xC0000094 (integer divide-by-zero). Device inspection showed eight channels, I24, a 1024-frame buffer and **zero default sample rate**, while valid supported rates were advertised. Our code created DSP at zero Hz before opening a stream. The fix negotiates an advertised rate (preferring 48 kHz), preserves the required channel count, and rejects the configuration cleanly if no valid rate exists. After the fix the same isolated Realtek ASIO probe exited successfully (0). The probe now prints ordinary startup errors to stderr when invoked directly; the normal startup wrapper still suppresses child output.

Driver enumeration saw Realtek ASIO available. Registry also contained ASIO UX2; its presence does not prove hardware availability. Home hardware may differ. No saved audio backend/device preferences were changed by the fix.
